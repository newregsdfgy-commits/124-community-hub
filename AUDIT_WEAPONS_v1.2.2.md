## Источник и границы проверки
Проведён полный статический разбор оружейного контроллера, привязок ввода, UI, профилей и lifecycle в актуальном исходнике. Это не проверка работы всех оружейных систем Roblox. Игровой клиент, серверная баллистика, Android-исполнитель и реальные отстрелы не доступны в этой сессии.

## Подтверждённые и исправленные дефекты
- W2-01 — счётчик активаций увеличивался только при включённом Control Recoil/No Recoil. При одном No Spread оставался 0. Теперь учитываются все сигналы Tool.Activated; отдельные счётчики для Tool/Mouse/Touch/Gamepad. «Пульсы» не выдаются за реальные попадания.
- W2-02 — при повторной записи оружейным скриптом нового положительного Spread/Attribute исходное значение для отката оставалось старым. Теперь перед каждым локальным изменением сохраняется последнее наблюдаемое положительное значение. При выключении записывается назад, только если клиентский параметр по-прежнему равен 0.
- W2-03 — отложенный post-shot проход мог исполняться после выключения/повторного включения функции при том же Tool. Добавлена проверка generation (сброс при очистке индекса).
- W2-04 — удаление Folder/Configuration с дочерними числовыми параметрами оставляло их подписки в кеше. После Deferred DescendantRemoving проверяются все проиндексированные кандидаты и отключаются вышедшие из Tool.
- W2-05 — после удаления текущего Tool выбиралось nil, даже если в Character оставалось другое Tool. При удалении теперь переобнаруживается оставшееся Tool.
- W2-06 — ошибки периодической/реактивной проверки могли теряться в pcall. Введена обёртка safeApplySpread и счётчики checks/writes/errors/restoreFailures/lastError. Запись Value и Attribute дополнена readback-проверкой.
- W2-07 — UI говорил «изменено» без уточнения, что работоспособность влияния на точность не доказана. Диагностика чётко отличает обнаружение клиентских параметров от фактической траектории.

## Совместимость по механизму
| Механизм | Статически поддерживаемые признаки | Ограничение |
|---|---|---|
| No Recoil | Tool.Activated, unprocessed MouseButton1, Gamepad ButtonR2, распознанные Touch Fire/Shoot/Attack/Trigger; вертикальная дельта pitch камеры | Нестандартная камера, ручное движение во время стрельбы, скрипты с иной последовательностью камеры; проверка на устройстве обязательна |
| No Spread | NumberValue/IntValue с разрешёнными именами, числовые Attributes в доступном дереве Tool; периодическое переобнаружение | Не переписывает скрытые локальные переменные ModuleScript, RemoteEvent, серверный RNG, серверные траектории, произвольную баллистику |
| Откат | Значения/атрибуты возвращаются, если по-прежнему 0; неуспешные записи остаются в pending | При конкурентной записи другого модуля состояние не является транзакционным; проверять в конкретной игре |
| AIM+Recoil | AIM получает приоритет управления камерой при активном захвате | Одновременная камера может блокировать локальную компенсацию, что сообщается диагностикой |

## Проверки и сценарии для QA
- Статические инварианты: оба entrypoint исходника идентичны; ключ и UI на месте; автоактивация No Recoil/No Spread из профилей запрещена; input и генерации событий сохранились.
- Девять сфокусированных Node.js тестов в `tests/Weapons2Compatibility.test.cjs`: исходники, отдельный No Spread режим, исходные значения, async generation, очистка watchers, fault isolation, camera/AIM, UI статус, автозагрузка.
- `tools/verify_release.py` расширен условиями Weapons 2.0, сохранив исходные viewport/lifecycle проверки.
- **CI подтверждён:** [GitHub Actions run 43045644213](https://github.com/newregsdfgy-commits/124-community-hub/actions/runs/43045644213) завершился SUCCESS: 49/49 статических release-assertions; 9/9 специализированных Node.js тестов; синтаксический разбор и бинарная компиляция Luau всех трёх файлов `Hub.lua`, `Visuals.lua`, `Start.lua` прошли.
- Отдельный workflow `.github/workflows/weapons-2-ci.yml` проверяет тесты и компиляцию Luau. Старый общий набор `node --test tests/*.test.cjs` содержит около 50 версионно-зависимых проверок от v1.1.x; его падение на v1.2.x не означает, что оружейный блок не компилируется. Старый CI оставлен в прежней области.
- Для реального теста: экипировать/снять два Tool; проверить одиночный/автоматический огонь; Mouse/Touch/Gamepad; AIM одновременно; сброс при респавне и повторном запуске; меняющийся Spread; включение/выключение No Spread; блокировки API; проверить `Output` после кнопки «Диагностика Weapons 2.0».

## Не выдавать за проверенное
Работа в реальном Roblox/исполнителе, количество кадров/нагрузка FPS, реальное изменение серверной траектории, совместимость с каждым оружием и отсутствие клиентских багов не проверены. Новая ветка тестовая и не заменяет main. Сохранены Purple Neon UI 2.0, ESP, AIM, FPS Booster, движение, музыка, профили и UI. Нужна отдельная проверка на устройстве перед переносом в main.
