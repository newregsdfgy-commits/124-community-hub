# 124 Community Visuals v1.1.19 — UI Redesign

**Дата:** 2026-11-02  
**Основа:** `v1.1.18-max-performance-test`  
**Ветка:** `v1.1.19-community-visuals-ui-test`  
**Основной запускаемый файл:** `Visuals.lua`  
**Совместимая копия:** `Hub.lua` (должна совпадать байт-в-байт)

## Дизайн по пользовательскому изображению

- Палитра: почти чёрный фиолетовый фон `#0D0516`, тёмно-фиолетовые карточки `#1F0D2C`, акцент `#A12EFF`, спокойные светлые надписи.
- ПК: боковая колонка 188 px, пять пунктов `Dashboard / Visuals / Aim / Performance / Settings`, активная позиция подсвечивается.
- Заголовок текущей страницы и пояснение расположены над содержимым справа, как в образце.
- Домашний Dashboard: 4 карточки реальных показателей FPS, оценки 1%-low FPS, ping и количества ESP-игроков; график 16 последних секунд FPS (без выдуманного «+24 FPS»).
- Quick Actions: `Open Performance`, `Enable ECO`, `Toggle Guard`, `Safety Stop`. Все четыре выполняют реальные действия Hub. Для Safety Stop требуется второе нажатие в течение четырёх секунд.
- Нижний информационный баннер с названием **124 Community Visuals**, без фальшивой рекламы премиума.
- Мобильный режим: пять нижних вкладок шириной `0.2 - 9px` и фиксированной высотой 40 px, а не узкая/неудобная боковая колонка. Dashboard с 2×2 показателями, вертикальным графиком и блоком быстрых действий, доступен скролл.
- Возвращение из бокового меню и изменение размера экрана не создают новую копию Dashboard.

## Почему не копировали действия Windows из картинки

Команды типа Flush DNS Cache, Restart Audio Driver, Optimize TCP/IP и Clear Standby List нельзя честно реализовать средствами обычного Roblox LocalScript. Они заменены на реальные безопасные действия, доступные существующему Hub, без претензии на изменение настроек ОС.

## Переименование и совместимость

Название интерфейса, пользовательские сообщения и основной файл — **124 Community Visuals**. Внутренние `env.ARMY124_CLEANUP`, `ARMY124_CONFIG_V09` и прочие технические ключи **не переименовывались**, чтобы поддержать безопасный hot-reload, загрузку старых настроек и откат.

`main` не менялась и всё ещё указывает на ранее опубликованную v1.1.16. Исходная v1.1.18 сохранена в собственной тестовой ветке.

## Производительность

- **Ноль дополнительных покадровых обработчиков** создано Dashboard.
- График FPS получает один реальный замер примерно в секунду из существующей метрики.
- Четыре карточки обновляются через существующий фоновый цикл UI; 1%-low рассчитывается не чаще раза в 3 секунды и только если Dashboard открыт.
- GUI выполнен на стандартных Frame/TextLabel/TextButton; без анимированных фонов, видео, внешних UI-библиотек и системных команд.
- Сохранены Performance Guard, Module CPU Monitor, Lazy Loading и все старые функции AIM/ESP/Recoil/MISC/CONFIG.

## Проверки

- Полный исходник получен обратно из GitHub, проверено точное совпадение SHA у `Visuals.lua` и `Hub.lua`.
- Выполнены статические проверки маршрутизации HOME/ESP/AIM/MISC/CFG, реальности FPS/Ping/1%-low/ESP и кнопок быстрого доступа, защиты Safety Stop, мобильных и ПК размеров.
- Лексический анализ скобок, строк и управляющих блоков Luau не выявил нарушений; обе большие области объявления `local` остаются ниже 200 в предварительном подсчёте.
- Основные участки AIM, Recoil, Bunny Hop, Chat, Booster при сравнении с v1.1.18 отличаются только пользовательским префиксом логов и комментариями.
- В репозитории предусмотрены 9 performance-model/source-contract тестов и 8 UI source-contract тестов. Workflow должен запускать Node-тесты и официальный `luau-compile` для обоих скриптов. **Результат их выполнения в GitHub Actions и исполнение Roblox / Delta / Xeno пока не подтверждены.**
- На практике отображение текста/перетаскивание на конкретном Android/ПК нужно проверить в Roblox, только после этого переносить в main.
