## 1. Performance Guard

**OFF по умолчанию, включается вручную через MISC → PERFORMANCE → Performance Guard.**

Guard не меняет `state.performanceMode`, настройки AIM и профили. При необходимости он снижает **только** частоту и количество графических примитивов ESP. Уровни:

| Уровень | Максимум ESP-целей | Максимум Box/Skeleton | Частота рисования ESP |
|---|---:|---:|---:|
| L0 (Guard спит) | как в AUTO/ECO/QUALITY | как в AUTO/ECO/QUALITY | как в AUTO/ECO/QUALITY |
| L1 | 6 | 4 | 12 Hz |
| L2 | 4 | 2 | 8 Hz |

Guard измеряет FPS раз в секунду. Переходит к L1 после 3 последовательных секунд FPS <39 **или** 3+ кадров от 50 мс в каждой секунде. Переходит к L2 после 3 секунд FPS <29 или 6+ долгих кадров. Снижает ограничения на один уровень после 8 последовательных хороших секунд (FPS >=55 без 50-мс задержек) и минимум 12 секунд после предыдущего переключения. При ручном выключении ограничения снимаются. Частота AIM остаётся прежней.

## 2. Module CPU Monitor

**OFF по умолчанию**; MISC → PERFORMANCE → Module CPU Monitor, затем «Нагрузка модулей (avg / peak)».

Шесть измеряемых участков: `AIM`, `Recoil`, `ESP Draw`, `ESP Scan`, `Booster Q`, `HUD`. Показаны среднее/пиковое **время вызова в мс** и количество измерений. Это измерение прошедшего времени в Luau через `os.clock()`, а не настоящий процент загрузки CPU / системный profiler. `Booster Q` — только пакеты обработки подгруженных объектов; полный первичный обход мира не включён. `HUD` включает фоновое обслуживание освещения/статусов. Когда монитор выключен, обёртки просто вызывают оригинальные функции без чтения `os.clock()` и записи статистики.

## 3. Lazy Loading

**ON по умолчанию**. Отдельные `ScreenGui` для Tracer и Box/Skeleton не создаются при холодном старте. Они создаются на первом реальном использовании соответствующей функции и затем переиспользуются. FOV ring остаётся небольшим eager-объектом сознательно, чтобы сохранить AIM UX. Настройка доступна в MISC → PERFORMANCE → Lazy Loading; при OFF создаёт недостающие слои сразу для совместимости. Объекты привязаны к штатному cleanup и списку `bootRoots`.

## 4. Профили и отказы

- Состояния `performanceGuard`, `moduleCpuMonitor`, `lazyLoading` входят в валидируемый список настроек CUSTOM; при автозагрузке `moduleCpuMonitor` принудительно OFF.
- Отключение Guard не перезаписывает сохранённую конфигурацию FPS/ESP; при повторном появлении игроков применяется исходная настройка.
- Existing ESP cache 3.5 секунды / 4 дополнительных скрытых объекта сохранён.
- Если Roblox ограничивает UI / Raycast / свойства и Booster не может обработать карту, первичный rollback из v1.1.17 остаётся.
- Новый код не добавляет HTTP-запросов, удалённых зависимостей или отдельного постоянного фонового worker.

## 5. Проверки и что они означают

- Получен полный `Hub.lua` из новой GitHub-ветки и сравнён с v1.1.17.
- Проведены 64 целевых статических проверки; один первоначальный чек дал ложный сигнал из-за слишком узкого поиска `perfTier`, остальные 63 подтвердили нужные свойства. Отдельная проверка уточнила, что AIM сохраняет старый `perfTier()`, а ESP использует `visualPerfTier()`.
- Лексический проход скобок, строк и блоков `function/if/for/while/repeat/end/until` — без найденных ошибок. В двух крупных областях приблизительно 136 и 99 объявлений `local`; это не полноценный подсчёт регистров/компиляция.
- Семь смоделированных сценариев Guard прошли: 60 FPS, единичная просадка, 35 FPS, 22 FPS, повторные 50-мс кадры, частые критические задержки и постепенное восстановление. Эти модели не исполняют Luau-код.
- Добавлены постоянные `tests/HubPerformance.test.cjs` (9 source-contract / model tests) и CI workflow; **фактический успешный запуск Node-тестов и Luau-компилятора не подтверждён в этом сеансе**.
- **Нельзя утверждать:** гарантированный прирост FPS, отсутствие ошибок executor, совместимость с каждым Roblox-патчем, прохождение фактического smoke test.

4. Проверить AIM с зарегистрированным Tool, переключение головы/тела/ног, FOV, Visible Check и Recoil; Guard должен влиять только на ESP visuals.
5. Для Performance Guard сравнить L0 → L1 → L2 в тесте с низким FPS (и последующее восстановление), убедиться в отсутствии зависания L2 после OFF.
6. Module CPU Monitor OFF: отсутствие статистики и минимум накладных расходов. ON: появление измерений AIM/Recoil/ESP, Booster Q при StreamingEnabled и HUD; после OFF данные не должны продолжать обновляться.
7. Замерить FPS, 1% Low, p99, число кадров >=50мс для «без Hub», v1.1.17 и v1.1.18 на одном сервере/месте, в том числе Booster OFF.
